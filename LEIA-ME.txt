DEVOPS: GITHUB ACTIONS

Branch sugerida:
devops/github-actions

Source:
develop

Objetivo:
Configurar Integração Contínua (CI) no GitHub para que os testes e verificações
do AutoStock sejam executados automaticamente a cada Pull Request e a cada push
para develop ou main.

O QUE ESTA ETAPA ADICIONA:

1. Backend - Django / Pytest
- Configura Python 3.12.
- Instala requirements.txt.
- Executa o check do Django.
- Executa toda a suíte pytest.
- Usa o settings_test criado anteriormente, com SQLite em memória.

2. Frontend - React / Vitest
- Configura Node.js 22.
- Instala as dependências.
- Executa npm test.
- Executa npm run build para conferir se o projeto compila.

3. Docker
- Valida o docker-compose.yml.
- Faz build dos containers para identificar problemas de Dockerfile/configuração.

4. Pull Request Template
- Adiciona um checklist padrão quando alguém abre Pull Request.

QUANDO A AUTOMAÇÃO RODA:
- Pull Request para develop.
- Pull Request para main.
- Push em develop.
- Push em main.
- Também pode ser iniciada manualmente pela aba Actions.

COMO APLICAR:
1. No GitHub Desktop, vá para develop.
2. Faça Fetch/Pull origin.
3. Crie:
   devops/github-actions
   Source: develop
4. Extraia este ZIP.
5. Copie a pasta .github para a raiz do AutoStock.
   A estrutura deve ficar:

   AutoStock/
   ├── .github/
   │   ├── workflows/
   │   │   └── ci.yml
   │   └── pull_request_template.md
   ├── backend/
   ├── frontend/
   └── docker-compose.yml

6. Faça o commit:
   devops: configura integracao continua com GitHub Actions

7. Push origin.
8. Abra Pull Request para develop.

AO ABRIR O PULL REQUEST:
O próprio GitHub deverá mostrar os checks:

- Backend - Django / Pytest
- Frontend - React / Vitest
- Docker - Validar configuração

Aguarde os três ficarem verdes antes do merge.

IMPORTANTE:
O arquivo frontend/package-lock.json deve estar versionado no GitHub.
Como ele foi criado na etapa test/frontend com npm install, confirme no
GitHub Desktop que ele foi incluído no commit anterior.

SE UM CHECK FICAR VERMELHO:
Abra o Pull Request -> Details no check que falhou -> leia a última mensagem
do log. Não faça o merge até corrigir.

ARQUIVOS DESTA BRANCH:
- .github/workflows/ci.yml
- .github/pull_request_template.md

Depois desta branch falta somente:
